# Vendored ontology agent contract

These files are copied unchanged from the ontology agent's source, `proto/ontology_agent/v1/`, at commit `9e1b6284420923efd71e405d17f899ee2c13b67f` (contract 4.7.0: 4.2.0 and five additive steps. 4.3.0 and 4.4.0 add `Audit`, which audits a page of a load's documents for what their reviews say the bundle lacks, `Check`, which checks a self-healing draft against its proposal, and Revise's `origin`, the approval of a self-healing fix; the foundry-heal-worker calls `Audit`, and Foundry calls no `Check` and sends no `origin`. 4.5.0 lets an Ask request set what each read of the graph may spend, `limits.read` (`wall_ms`, `scan_entities`), and a read stopped at one, or at `helix.timeout_secs`, names it in its `tool_result`'s error. 4.6.0 adds `Read` and `Ask` taking `visibility`, what a reader holds of a load, the `view` read and the `not_visible` failure, and a query's rows taking `offset`, which a reader of part of a load can't use; a reader's Ask reads within the same `limits.read`. 4.7.0 adds valid time to `Ask`'s result: a cited version's `valid`, when its state held in the world (`from`, `to`, and `day`, a source's day with no time of day, whose `from` is the next midnight UTC), and every `cannot_answer`'s `kind`, what the load lacks (`uncovered`, `after_as_of`, `undeclared_relation`, `undeclared_property`, `absent`). Any Ask with `visibility` (every grantee's question, whoever holds all of the load included) is offered no `history_of`, `changes` or `helix_query` and no `get_entity` `as_of`, and answers another time from what `get_entity` shows; a reader of only part of a load also sees no `valid` or `past`, so its questions about another time or a change end `cannot_answer` with `kind` `uncovered`, and one about a time after it asked still `after_as_of`. `valid` is new on a type that refuses unknown fields, so a check against 4.6.0's schemas refuses an answer citing one. Visibility was first vendored from `0cd3dff66a2275c2841ace8d861fdfc967c40cb7`, which called it 4.3.0, a number dev-3's heal contract already had: an agent built from that commit reports 4.3.0 and isn't this contract. 4.2.0 was 4.1.1 and graph apply, all additive: `Ingest` takes `reload: "diff"`, which brings a load up to new data in place, and a `changes` source access, a table's changes since a position; it answers `applied`, `diff_unsupported` and `position_mismatch`. `Extract` takes `remove`, documents to retract from the load. `Compare` compares two loads of one version). Its `schema/catalog.json` prices OpenAI's and Amazon Bedrock's models as well as Anthropic's; Azure deployments are priced from OpenAI's rows, and a Bedrock inference profile with no row of its own as the model it runs. The `ontology-agent` image Foundry runs beside its workers must be built from a commit that serves this contract.

| File | What it is |
|---|---|
| `agent.proto` | `ontology_agent.v1.Agent`: `Turn` streams events then one result; `Ingest` creates a load and fills it, `Extract` adds documents to a load and `DeleteLoad` removes one, the same way; `Read` reads a load with its version's rules applied, and `Compare` two loads of one version, both unary; `Ask` answers one question over a load, streaming events then one result; `Clues` streams the people a load's `[enrichments]` item could look up; `Revise` dry-runs edits of a draft against a load, unary; `Audit` audits a page of a load's documents (the foundry-heal-worker calls it) and `Check` a self-healing draft, both unary; `Title` writes a generation's title and `Probe` checks an endpoint's models for each role, both unary; `GetInfo` reports the contract version and the provider kinds the build calls. `Turn`, `Ask`, `Extract`, `Title` and `Probe` run on the models their request names, the endpoint's key in the call's `x-foundry-model-key` metadata |

Do not edit them here. To move to a new agent build:

1. Copy `agent.proto` and every file in `schema/` from the agent's commit and update the commit above.
2. Set `ontologyagent.ContractVersion` (`ontologyagent/contract.go`) to the first field of `schema/VERSION`.
3. From the module's root, run `buf generate && buf generate --template buf.internal.gen.yaml`, then `go test ./ontologyagent/`. The tests check every request the workers and foundry-read build against the request schemas, the fixtures the decoders are tested on against the result and event schemas, and the version against `VERSION`.
4. Build the agent image from that commit and deploy it with this backend.

Each generation, graph job, read, question, title and probe checks the sidecar's `GetInfo.contract_version` first, and that `GetInfo.providers` holds the workspace's provider kind. While it differs from `ContractVersion`, every generation, graph job and question the workers claim fails for good and every read is refused, so deploy the image and the backend together.
